## Deployment appendix — exact planned operator interface

All commands run on the checked-out Brev VM over SSH, with Docker available. Ivan is the sole deployment operator/writer; another backend worker may build DB/calculator while the GPU download runs. `bootstrap.sh` and companions must be implemented by B06, not treated as pre-existing tooling.

1. Verify actual instance quote/balance including any disk cost. Record instance ID, GPU name/VRAM, elapsed time and spend cap in `infra/brev/deployment.md`. Target a single small NVIDIA GPU capable of the selected model/context; no specific GPU SKU or hourly price is assumed. Stop provisioning if it cannot fit the remaining $50 allocation. Do not create an instance during plan generation.
2. `bootstrap.sh` runs host `nvidia-smi`, checks Docker Compose + NVIDIA Container Toolkit, then selects one image. NIM feasibility deadline10min: exact accessible image/model/profile must fit; registry/model gating or oversized download triggers the specified llama.cpp CUDA/Qwen1.5B fallback. Pin real image digest and model revision/file SHA-256. Optional NGC credential only if actual pull/model requires it; never expose it to GPU inference request or web.
3. Fallback command inside `gpu-specialist`: `llama-server -m /models/qwen2.5-1.5b-instruct-q4_k_m.gguf --alias atlas-specialist --host 0.0.0.0 --port 8000 --n-gpu-layers 99 --ctx-size 8192 --parallel 1`. Check the pinned image entrypoint; use arguments directly when it already launches llama-server. Set GPU_MODEL_ID=atlas-specialist only for this confirmed alias. Verify actual layer offload, not merely requested flags. A NIM profile uses its documented startup/options and actual /v1/models ID, with identical app-level G01/G02 contract. Do not guess a NIM image identifier.
4. Overlay defines `gpu-specialist` with NVIDIA GPU reservation (driver nvidia, count1, capabilities gpu), model volume and private Compose network. Mount deployment evidence directory read-only into API at GPU_VERIFICATION_PATH; no socket or public8000 mapping. Root Compose supplies web/api/db; readiness does not block API startup. API image needs pnpm/tsx and smoke files available for hackathon verification; B01/B11 own that image.
5. `gpu-smoke.sh` creates one actual G01 body from `smoke-request.json` with configured model: fixed classification rubric and a synthetic numeric candidate with recurrenceCount>=3 and borderline size, max_tokens4096, temperature0, stream false. Use Docker-network access from a pinned small curl container (pin its verified image in overlay as an optional tools profile if needed; it is a test helper, not a permanent service). Equivalent command is `docker compose -f compose.yaml -f infra/brev/compose.gpu.yaml run --rm gpu-probe -fsS --max-time 10 -H 'Content-Type: application/json' --data-binary @/probe/request.json http://gpu-specialist:8000/v1/chat/completions`; script constructs /probe/request.json and mounts it read-only, never embeds secrets. Readiness equivalent: same helper with `--max-time 2 http://gpu-specialist:8000/v1/models`. Raw inference is validated against candidate IDs/label/confidence before success; AI03 independently applies shared Zod validation. Curl helper has no GPU and is never counted as workload execution.
6. `verify-deployment.sh` records `docker compose ... ps`, actual container/image IDs, model checksum/profile, host GPU identity, container GPU visibility and model GPU-offload logs. Run a CUDA operation with the selected runtime/warmup and correlate inference response/timestamps with the workload PID and GPU compute telemetry (e.g. NVIDIA sampling during repeated requests or profiler when a short request is missed). Record real evidence; a missing sample is inconclusive, not proof. `nvidia-smi` alone/VRAM/HTTP200 cannot satisfy GPU execution. Create the verification record only after successful proof; it excludes per-request fields later appended by AI03.
7. `restart.sh` removes/invalidates verification record **before** restarting gpu-specialist, waits bounded readiness (startup max10min; user inference still10s), reruns smoke and verify and refreshes API's read-only directory mount. Model/instance/container changes require this path. Unexpected crash/restart leaves record untrusted: startup wrapper must clear it and require re-verification; disable automatic restart-unless-stopped that could preserve stale success. Container startup identity is associated with the generated record; API refuses a record without current deployment lease. No remote hardware attestation is claimed.

```text
bash infra/brev/bootstrap.sh
nvidia-smi
docker compose -f compose.yaml -f infra/brev/compose.gpu.yaml up -d gpu-specialist
bash infra/brev/gpu-smoke.sh
bash infra/brev/verify-deployment.sh
docker compose -f compose.yaml -f infra/brev/compose.gpu.yaml stop gpu-specialist
bash infra/brev/restart.sh
```

Stop container only for reliability drill; stop the actual Brev instance through its verified console/CLI after the final demonstration to end compute billing. Record the actual action/status.
